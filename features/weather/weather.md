# MOIPJI — 개발 명세서

> 오늘 날씨에, 모입지?

- Version: 1.19
- Python: 3.14
- Framework: Streamlit 1.66
- Weather API: OpenWeatherMap (무료 플랜: 현재 날씨 + 5일/3시간 예보 + 대기질 예보)
- Entry Point: `weather.py`
- Git Branch: `feature/weather`
- 개발 방식: 규칙 기반 추천 (AI API 사용하지 않음)

## 1. 서비스 개요

MOIPJI는 날씨와 사용자가 선택한 패션 스타일을 조합해 오늘의 옷차림을 추천하는 모바일 중심 웹앱이다.

**핵심 UX 콘셉트: 날씨는 숫자로, 옷차림은 말로.**

날씨 수치보다 사용자가 무엇을 입어야 하는지 먼저 알려주고, 위트 있는 UX Writing과 직관적인 코디 카드로 결과를 전달한다. 추천한 코디는 도트 캐릭터(미니미)가 직접 입고 보여 주며, 마음에 드는 코디는 옷장에 저장한다.

## 2. 핵심 기능

### F00. 첫 화면과 내 정보 설정

- 들어올 때마다(새로고침 포함) 본 화면 대신 **게임처럼 한 단계에 하나씩** 묻는 첫 화면을 보여 준다
  - 단계: ① 닉네임 → ② 성별 → ③ 지역(국가 → 도시) → ④ 꾸미기(눈·피부색·헤어) → ⑤ 시작
  - 맨 위 진행 표시: "STEP 2 / 5"와 "2단계 / 5단계, 앞으로 3단계 남았어요", 단계 막대 5칸(지난 단계 ✓, 지금 단계 강조, 남은 단계 흐리게)
  - 왼쪽에 **안내 캐릭터 모입**을 상반신만 크게 보여 준다. 말하기(입 벙긋)·안녕 손 흔들기·박수·활짝 웃기·눈 깜빡임을 무작위 순서로 이어서 반복한다 (안녕으로 시작, 단계마다 순서가 바뀜, 움직임 줄이기면 첫 장면만)
  - 오른쪽 말풍선에서 캐릭터가 단계마다 말을 건다 (예: "구름이, 반가워! 어떤 코디를 추천해 줄까?"). 고른 성별·얼굴이 캐릭터에 바로 반영되어 미리보기 역할을 한다
  - "이전" / "다음" 버튼. 닉네임·성별이 비어 있으면 넘어가지 않고 "닉네임을 입력해 주세요." / "성별을 골라 주세요."를 보여 준다. 이전으로 돌아가도 입력한 값은 그대로다
  - 마지막 단계는 요약(닉네임·성별·국가·도시)과 "MOIPJI 시작하기"
  - 닉네임(필수, 10자)은 추천 카드 질문에서 부른다 (예: "구름이님, 오늘 뭐 입지?")
- 키·몸무게는 묻지 않는다 (첫 화면·설정 모두). 미니미는 보통 체형으로 그린다
- 반영: 성별 → 추천 코디·스타일 목록·미니미(머리·어깨·허리선·옷 재단), 지역 → 처음 보여 줄 지역
- **미니미 얼굴**(첫 화면·설정 모두): 눈 3가지(동그란 눈·차분한 눈·웃는 눈), 피부색 5가지(아주 밝은·밝은·중간·구릿빛·짙은), 헤어 5가지(단발·긴 머리·묶은 머리·짧은 커트·곱슬 펌). 고르는 대로 미니미가 바뀐다 (첫 화면은 안내 캐릭터, 설정 창은 작은 미리보기)
  - 성별 기본값: 여성은 동그란 눈·단발, 남성은 차분한 눈(하이라이트 없이 가로로 긴 눈)·짧은 커트. 남성은 눈썹을 조금 길고 진하게, 볼터치를 작게 그린다
  - 성별을 바꿀 때 눈·헤어가 다른 성별 기본값 그대로면 새 성별 기본값으로 따라 바뀐다
  - 피부색 칩은 그 색으로 칠하고 이름을 함께 적는다
- 저장 창의 태그 칩은 14px 글자에 둥근 칩으로 크게 보여 준다. 저장 창·설정 창은 모서리를 둥글게(20px) 한다
- **설정**: 맨 위 화면 모드(브라이트/어두움) 옆 톱니바퀴 버튼 → "내 정보 설정" 창에서 닉네임·성별·지역(국가 → 도시)·얼굴을 고치고 저장한다. 저장하면 창이 닫히고 화면이 바로 바뀐다
  - 창 맨 위에 주의 안내: 저장하면 지금 고른 아이템·색과 챙긴 준비물이 초기화되고, 내 정보는 이번 접속에만 저장되어 새로고침하면 처음 화면으로 돌아간다
  - 저장하면 실제로 초기화한다: 스타일 안에서 고른 아이템, 옷·준비물 색, 챙기기, 팔레트·둘러보기 토글, 말풍선 위치 (외출 시간·스타일은 그대로)
- 머리글의 지역 선택은 이번 접속에서만 바꾸는 것이고, 처음 보여 줄 지역은 설정에서 바꾼다
- 내 정보는 이번 접속(Streamlit 세션)에만 둔다. 파일에 저장하지 않아서 새로고침하면 처음 화면부터 다시 입력한다. 첫 화면에도 이 안내를 적는다

### F01. 지역별 날씨 조회

- 기본 지역: 대한민국 서울. **국가를 먼저 고르고 그 나라 도시를 고른다** (`data/cities.json`, 도시마다 `country`)
  - 대한민국 16곳 + 해외: 몰디브(말레), 필리핀(마닐라·세부), 태국(방콕·푸껫), 일본(도쿄·오사카·삿포로·오키나와), 중국(베이징·상하이·하얼빈), 대만(타이베이·가오슝), 미국(뉴욕·로스앤젤레스·호놀룰루·앵커리지)
  - 한국과 다른 계절을 보려고 넣었다: 한국이 추울 때 동남아·몰디브·하와이는 한여름, 하얼빈·삿포로·앵커리지는 혹한
  - 나라를 바꾸면 도시는 그 나라 첫 도시로 바뀐다. 시각은 모두 그 도시 현지 시각
  - 도시 이름은 겹치지 않게 둔다 (내 정보에 도시 이름으로 저장)
- 현재 기온, 체감온도, 습도, 풍속, 날씨 상태(아이콘 + 한글 이름) 표시
- 날씨 상태는 OpenWeather 상태 코드를 한글 이름과 Material 아이콘으로 바꿔 보여 준다 (예: 800 → 맑음, 밤에는 달 아이콘)
- OpenWeatherMap의 실제 데이터만 사용하고, 오류·누락 시 안내를 보여 준다
- 데이터 기준 시각을 함께 보여 준다 (관측·예보 시각, 불러온 시각)
- "날씨 및 추천 근거" 접기 머리줄은 열림·포커스·마우스 올림 상태에서도 유리 바탕 + 테마 글자색을 쓴다 (흰 바탕에 흰 글자가 되지 않게)

### F02. 외출 시간 선택 (시간별 날씨)

오전·오후·저녁 3개 탭 대신, 하루 전체를 가로로 스크롤하며 외출할 시간을 고른다.

- 시간 칸: **오늘 0시부터 내일 21시까지 48시간**, 3시간 간격 16칸을 한 줄로 이어 보여 준다 (무료 예보가 3시간 간격이라서). 자정을 넘기는 외출도 고를 수 있다
  - 내일이 시작되는 칸은 "내일 0시"로 쓰고 앞에 구분선을 둔다
  - 칸 아래에 항상 보이는 전용 스크롤바를 둔다 (누르기·끌기·좌우 화살표로 이동). 브라우저 기본 스크롤바는 휴대폰·맥에서 잘 안 보여 숨긴다
- 날짜 버튼 **오늘 / 내일**: 고른 칸이 있는 날짜가 선택 상태로 보이고(오늘에 이어 내일까지 고르면 둘 다), 누르면 그 날짜 칸으로 이동한다
- **날씨 새로고침** 버튼: "외출 시간 확정" 옆. 캐시를 비우고 OpenWeather에서 다시 불러온다
  - 각 칸에 날씨 아이콘과 기온을 표시하고, 지금 시각이 든 칸은 "지금"으로 표시·강조한다
  - 오늘 이미 지난 칸은 흐리게 "—"로 표시한다 (무료 API는 과거 데이터를 주지 않음)
- **여러 칸을 고른 뒤 "외출 시간 확정"을 눌러야 추천에 반영된다**
  - 확정 전에는 "고른 시간을 확정하면 추천이 바뀌어요"를 표시한다
  - 이어진 칸은 "9시~18시", 떨어진 칸은 "9시, 18시", 자정을 넘기면 "21시~내일 3시"로 부른다
  - 질문·문구의 "오늘/내일"과 히어로 날짜는 외출 시작 칸 기준이다. 자정을 넘기면 히어로 날짜는 "10/22(목)~10/23(금)"
- 데이터가 없는 칸만 골랐으면 "아직 데이터가 없어요" 또는 "지난 시간이라 데이터가 없어요"를 표시한다
- 예보 시각은 선택 지역의 현지 시각으로 처리하고, 현재 관측과 예보를 구분해 표시한다

### F03. 스타일 선택

| 스타일 | 특징 |
|---|---|
| Simple | 기본 아이템 중심, 깔끔한 조합 |
| Modern | 정돈된 실루엣, 셔츠와 슬랙스 |
| Casual | 편안한 일상복, 데님과 맨투맨 |
| Lovely (여성) | 부드러운 색감, 가디건과 스커트 |
| Dandy (남성) | 셔츠·블레이저·코트로 단정하게 |
| Street | 오버핏, 후드와 와이드 팬츠 |

- 성별마다 5개 스타일: 여성은 Lovely, 남성은 Dandy가 들어간다. 나머지 4개는 함께 쓴다 (치마·블라우스가 없는 코디)
- 성별을 바꿔 지금 스타일이 없어지면 Simple로 돌아간다
- 기본 선택값: Simple
- "옷 고르기" 영역(상의·하의·아우터 카드 위)에 둔다
- 스타일을 바꾸면 그 스타일의 날씨 추천 코디에서 시작한다. 이후 아이템은 사용자가 "선택" 버튼으로 하나씩 바꾼다 (F05)

### F04. 체감온도 기반 코디 추천

| 코드 | 체감온도 | 기본 추천 |
|---|---|---|
| T01 | 28°C 이상 | 반팔, 반바지, 얇은 소재 |
| T02 | 23~27°C | 반팔, 얇은 셔츠, 면바지 |
| T03 | 17~22°C | 긴팔, 가디건, 얇은 재킷 |
| T04 | 12~16°C | 니트, 재킷, 트렌치코트 |
| T05 | 6~11°C | 두꺼운 니트, 코트 |
| T06 | 5°C 이하 | 패딩, 목도리, 보온 의류 |

- **옷은 외출 시간 중 체감온도가 가장 낮은 때를 기준으로 고른다**
- 체감온도는 정수로 반올림(사사오입)해 구간을 정한다. 화면에 보이는 온도와 구간이 항상 일치한다
- 스타일 × 구간 = 성별마다 30개 코디 (`data/outfits.json`, 공용 24 + 여성 Lovely 6 + 남성 Dandy 6 = 36개), 상의·하의·아우터를 각각 추천한다
- 아우터가 필요 없으면 '아우터 없이도 좋아요'로 표시한다

**준비물 (외출 시간 전체로 판단, 위에서부터 우선순위)**

| 조건 | 준비물 |
|---|---|
| 강수확률 50% 이상 (한 칸이라도) | 우산 |
| 미세먼지(PM10) 81㎍/㎥ 이상 또는 초미세먼지(PM2.5) 36㎍/㎥ 이상 (외출 중 가장 나쁠 때, 환경부 '나쁨' 기준) | 마스크 |
| 최저 체감 0°C 이하 | 핫팩 |
| 최저 체감 3°C 이하 | 귀마개 |
| 최고 체감 28°C 이상 | 물 |
| 기온 차 10°C 이상 (외출 중, 한 칸이면 그날 일교차) | 여벌 가디건 |
| 풍속 8m/s 이상 (가장 셀 때) | 바람막이 |
| 맑은 낮 + 최고 체감 25°C 이상 | 양산 |
| 맑은 낮 (맑음·구름 조금) | 선글라스 |

- 코디에 딸린 소품(목도리·장갑·비니·캡 모자·버킷햇·귀마개·기모 스타킹 등)도 준비물로 함께 추천한다
- 무료 API에는 자외선 정보가 없어서 "햇빛 쨍쨍"은 맑은 낮으로 판단한다
- 미세먼지는 OpenWeather 대기질 예보(시간별)에서 외출 칸 날씨 시각 ±90분의 최댓값을 본다. 불러오지 못하면 마스크 추천만 빠지고, 근거에 그 사실을 적는다
- 여러 조건이 겹치면 우선순위가 가장 높은 안내를 추천 카드에 강조한다
- 기준값은 `data/rules.json`의 `thresholds`에서 조정한다

### F05. 개별 아이템 (옷 고르기)

- 상의·하의·아우터 카드: 지금 입은 아이템의 도트 옷 아이콘, 아이템명, 추천 이유
- **다른 아이템 둘러보기** 버튼을 눌러야 아이템 고르기가 보인다 (기본은 닫힘, 열리면 "둘러보기 닫기"). "추천 코디로 되돌리기"와 같은 버튼 모양으로 왼쪽부터 나란히 둔다. 좁은 화면(480px 이하)에서는 반씩 나눠 한 줄에 두고 글자를 낱말 단위로 줄바꿈한다
- **스타일 안에서 아이템 고르기**: 상의·하의·아우터 탭마다 그 스타일 코디 6개에 나오는 아이템을 카드로 보여 주고, "선택"을 누르면 그 아이템으로 바꾼다
  - 카드마다 "색상" 버튼(팝오버)으로 그 아이템 색을 고른다. 고른 색은 카드 아이콘·입은 옷·미니미에 바로 반영되고, 팝오버를 닫아도 남는다
  - 코디 밖 아우터 `closet_extras`도 모든 스타일 아우터 탭에 나온다: **가죽 자켓**(17~22°C, 12~16°C용, 광택·지퍼), **숏 경량 패딩**(12~16°C, 6~11°C용, 촘촘한 퀼팅)
- **원피스·세트 탭**: 상의+하의를 한 벌로 대신한다. 맨 앞 "상의·하의 따로 입기"로 벗는다. 원피스를 입은 뒤 상의나 하의를 고르면 원피스는 벗는다
  - 여성: 오피스 H라인 원피스, 하객룩 플레어 원피스, 트위드 자켓 스커트 세트, 데이트룩 미니 원피스, 롱 니트 원피스, 리조트 맥시 원피스, 와이드 팬츠 셋업 (하의가 바지인 세트도 있다)
  - 남성: 수트 셋업, 린넨 셔츠 반바지 셋업, 하와이안 리조트 셋업, 니트 셋업 / 함께: 트레이닝 셋업
  - 원피스는 허리선·밑단 없이 한 장으로 이어 그리고(onepiece), 세트는 같은 색 위아래로 그린다. 색을 고르면 한 벌 전체가 바뀐다
  - 원피스를 입으면 옷 카드와 옷장 칸도 "원피스·세트 + 아우터" 두 칸이 된다
- 계절 아이템 (모든 스타일, 둘러보기에서 고름): 민소매 탑(여성), 하와이안 셔츠, 보드 반바지 (더운 나라), 헤비 다운 파카 (혹한 도시)
- **기타 탭**: 우산·양산·선글라스·안경·마스크·물·핫팩·바람막이·여벌 가디건·목도리·장갑·모자·귀마개·기모 스타킹을 모두 카드로 보여 준다
  - 오늘 추천된 것은 "추천"과 추천 이유, 나머지는 "필요할 때 직접 챙겨요."
  - "챙기기"/"빼기" 버튼과 "색상" 버튼. '챙길 것' 카드·말풍선 버튼과 같은 상태를 쓴다
  - **중복 착용 금지**: 안경·선글라스 중 하나, 모자(비니·캡·버킷햇) 중 하나, 우산·양산 중 하나. 하나를 챙기면 같은 묶음의 다른 것은 빠지고 알려 준다 (귀마개는 모자와 함께 가능)
  - **겹쳐 입기**: 가디건류(가디건·셔츠)끼리, 자켓류(자켓·트렌치·코트·패딩)끼리는 하나만. 가디건류 아우터를 입으면 여벌 가디건, 자켓류 아우터를 입으면 바람막이를 고를 수 없다(버튼이 꺼지고 이유를 적는다). 아우터를 바꿔 겹치게 되면 그 준비물은 자동으로 뺀다. 가디건 + 자켓 조합은 된다
  - 처음에는 날씨 추천 코디를 입고 있다. 추천 아이템에는 "추천", 입고 있는 아이템에는 "입는 중"을 표시한다
  - 카드마다 원래 어울리는 체감 구간을 적는다 (예: "28°C 이상용"). 아우터는 "아우터 없이도 좋아요"도 고를 수 있다
  - 다른 카테고리로도 입을 수 있는 아이템은 양쪽에 나온다 (`outfits.json` 아이템의 `as`). 얇은 화이트 셔츠는 아우터이면서 상의로도 고를 수 있다
  - 고른 조합은 스타일마다 기억하고, "추천 코디로 되돌리기"로 고른 아이템과 색을 모두 되돌린다 (아이템이나 색을 바꿨을 때만 누를 수 있다)
  - 고른 조합이 미니미·저장 정보에 반영된다. 준비물 추천은 날씨와 추천 코디 기준 그대로다
  - 카드는 고정 너비로 줄바꿈되어 휴대폰에서 2칸, 넓은 화면에서 4칸씩 보인다
- **색상 선택 팔레트**: 카드마다 토글을 켜면 컬러칩 16개(기본 + 15색)가 나오고, 고른 색이 아이콘·미니미·저장 정보에 반영된다
  - 칩에는 색 이름을 함께 적고, 칩 밝기에 따라 글자색을 바꿔 읽기 쉽게 한다
  - 색은 아이템마다 기억한다 (같은 트렌치코트는 다른 스타일에서도 같은 색)
  - 고른 색은 이름에도 반영된다: 터틀넥 니트 + 화이트 → "화이트 터틀넥 니트", 크림 니트 + 화이트 → "화이트 니트"
- 완성 룩 이미지는 실제 파일이 있을 때만 보여 준다. 없으면 미니미가 완성 룩 역할을 한다

### F06. 미니미 (코디를 입은 도트 캐릭터)

- 추천 코디를 그대로 입은 도트 캐릭터를 바깥 풍경 위에 보여 준다 (이미지 파일 없이 코드로 그림, `minimi.py`)
  - 약 6.5등신 패션 일러스트 비율, 옷 명암·목선·주름·라펠·벨트·퀼팅 등 디테일 포함
  - 풍경은 날씨에 따라 바뀐다: 맑은 낮(해), 밤(달·별·불 켜진 건물), 흐림, 비(빗줄기·물웅덩이), 눈(눈 덮인 길·나무)
- **챙긴 준비물만** 미니미가 들거나 쓴다 (우산과 양산은 함께 들지 않는다)
- **포즈**: 우산·양산은 오른팔을 굽혀 들어 올려 머리 위로 쓰고, 물·핫팩은 왼팔을 굽혀 몸 앞에 든다. 선글라스·마스크는 쓴 채로 팔을 내린다
  - 마스크는 코와 입을 덮고 귀에 끈을 건다. 귀마개는 모자와 따로라 비니 위에도 쓴다
  - 우산 그림: 사람을 가릴 만큼 큰 돔 캐노피(지름 43px, 오른손에 들어도 왼쪽 어깨 바깥까지 덮음), 꼭지에서 뻗는 살 8개, 물결 가장자리, 머리 위로 길게 올라간 우산대, J자 손잡이 (양산은 흰 레이스 가장자리)
  - 펼친 우산 아래(가장자리에서 발끝까지)는 비·눈을 그리지 않아 비를 막아 주는 모습이 된다
  - 옷장 썸네일·저장 창 미니미는 빈 여백을 잘라 그린다 (우산 자리 때문에 작아지지 않게)
  - 준비물을 **챙긴 그 순간에만** 그 준비물의 동작을 한 번 보여 준다 (장면당 0.35초). 다른 것을 바꿔 다시 그릴 때는 움직이지 않는다
    - 우산·양산: 서 있다가 → 접은 우산을 들어 올리고 → 펼친다
    - 물: 병을 입에 대고 눈을 감고 꿀꺽 마신다 → 몸 앞에 든다
    - 핫팩: 쥔 손을 위아래로 흔든다 (흔들 때 온기 점)
    - 선글라스·안경: 손끝으로 코받침을 밀어 1px 추켜올린다
    - 마스크: 주먹을 입에 대고 눈을 질끈 감으며 콜록, 숨이 퍼진다 (두 번)
    - 목도리·머플러: 바람에 머리칼과 목도리 끝이 오른쪽으로 휘날린다
    - 장갑: 짝짝 박수 두 번 → 내린다
    - 여벌 가디건: 잠시 웃는 눈으로 바뀌며 만세 → 돌아온다
    - 모자(비니·캡·버킷햇)·귀마개: 경례하듯 손끝으로 모자를 만진다 → 내린다
  - 옷장 썸네일·저장 창은 마지막 자세만 보여 준다
  - 화면 밖에 있는 동안 브라우저가 움직임을 멈추므로, 아래 '챙길 것'에서 챙긴 뒤 위로 올라오면 그때 동작이 보인다
- **움직이는 배경**: 구름이 천천히 좌우로 흐르고, 비·눈이 계속 내리고(28px 주기로 끊김 없이 반복), 밤에는 별이 반짝인다. 움직임 줄이기 설정이면 멈추고 마지막 자세만 보인다
- **말풍선**: 풍경 위 하늘 쪽에 "다른 건 챙길 것 없나?"를 먼저 보여 주고, 이어서 준비물별 랜덤 문장을 보여 준다
  - 준비물 이름은 강조색(#C2410C)과 도트식 굵게로 표시한다
  - `<` `>`로 다른 준비물을 둘러본다 (1/5, 2/5 …)
- `<` **○○ 챙기기** `>` 버튼: 말풍선이 보여 주는 준비물 하나만 챙기고, 챙긴 뒤에는 "○○ 챙기기 취소"로 바뀐다

### F07. 챙길 것

- 추천 준비물을 아이템처럼 도트 아이콘 카드로 보여 주고, 카드마다 "챙기기" 토글을 둔다
- "추천 n개 중 m개 챙겼어요"로 진행 상황을 보여 준다
- 말풍선의 챙기기 버튼과 같은 상태를 쓴다
- **색상 선택 팔레트**: 카드마다 토글을 켜면 옷과 같은 컬러칩(기본 + 15색)이 나온다. 고른 색이 아이콘·미니미(챙긴 경우)·가방 칸·옷장에 반영된다
  - 고른 색은 위젯 밖에 기억해서, 팔레트를 닫거나 같은 색을 고르는 곳(옷 카드·둘러보기)이 여러 군데여도 값이 같다

### F08. 내 옷장

- **저장 창 (아이템 등록)**: 게임 장비창처럼 미니미 + 장비 칸(상의·하의·아우터, 색 반영 이름과 아이콘) + 가방 칸(챙긴 준비물, 5칸)을 보여 주고, 칸이 하나씩 채워지는 연출을 한다
- 저장할 이름 입력 (비우면 "10/23(금) 9시~18시 흐림 Simple 코디" 같은 기본 이름)
- 태그: 기본 태그 12개(여행 코디, 직딩룩, 백수룩, 데이트룩, 꾸안꾸룩 등) 중 고르거나 새로 입력해 추가 (최대 5개, 12자). 추가한 태그는 다음부터 목록에 나온다
- 같은 코디(지역·날짜·외출 시간·스타일·고른 아이템 조합·색·챙긴 준비물과 그 색이 같은 것)는 한 번만 저장한다
- 썸네일 미니미는 저장한 장비 칸(모양·색)과 준비물 색, 저장할 때의 체형·얼굴로 다시 그린다. 성별이 다르면 다른 코디로 저장한다
- 옷장 보기: **리스트**(한 줄 요약) / **썸네일**(미니미 카드) 전환, 아이템 아이콘 줄, 이름·태그 표시, "옷장에서 빼기"

## 3. 이미지 구현

- 기본 그림은 모두 코드로 그린다: 미니미·풍경(`render_scene`), 옷 아이콘(`render_garment`), 준비물 아이콘(`render_supply`)
- 옷마다 `outfits.json`의 `pixel` 값(모양·색·디테일)으로 그림을 정하므로, 추천 아이템과 그림이 항상 일치한다
- 실제 완성 룩·아이템 이미지는 추후 제작해 넣으면 자동으로 함께 보여 준다
  - 제작 규격과 파일명 규칙은 `weather_image.md`를 따른다
- 실제 이미지가 없는 상태에서 임의의 이미지를 추천 결과로 표시하지 않는다
- 이미지 생성 API 및 사용자 이미지 업로드 기능은 구현하지 않는다

```text
assets/outfits/simple_T04_01.webp      # 완성 룩: {style}_{temperature_code}_{number}
assets/items/knit_turtleneck.webp      # 아이템: {item_id}
```

## 4. OpenWeatherMap API

공식 문서: https://openweathermap.org/api

### 4.1 Current Weather API

Endpoint: `https://api.openweathermap.org/data/2.5/weather`

Parameters: `lat`, `lon`, `appid`, `units=metric`, `lang=kr`

사용 필드: `main.temp`, `main.feels_like`, `main.humidity`, `weather[0].id`, `weather[0].description`, `weather[0].icon`, `wind.speed`, `dt`, `timezone`

### 4.2 5 Day / 3 Hour Forecast API

Endpoint: `https://api.openweathermap.org/data/2.5/forecast`

Parameters: `lat`, `lon`, `appid`, `units=metric`, `lang=kr`

사용 필드: `list[].dt`, `list[].main.temp`, `list[].main.feels_like`, `list[].main.humidity`, `list[].pop`, `list[].weather`, `list[].wind.speed`, `city.timezone`

### 데이터 처리

- 3시간 간격 예보로 그날 0시~21시 칸을 만든다. 지금 시각이 든 칸은 현재 관측을 쓴다
- 현재 관측에는 강수확률이 없으므로 3시간 안의 가장 가까운 예보 값을 쓴다
- 외출 시간 안의 최고·최저 기온 차이로 기온 차를, 그날 예보로 일교차를 계산한다. 예보가 부족하면 안내를 생략한다
- 예보를 불러오지 못하면 현재 날씨만으로 화면을 그리고 그 사실을 알린다
- API 응답 시각을 선택 지역의 현지 시간으로 변환한다
- 임의의 기상 데이터를 생성하지 않는다

### API Key 관리

환경변수: `OPENWEATHER_API_KEY` (팀 공통 이름 `WEATHER_KEY`도 읽는다)

- 로컬: `features/weather/.env`
- 배포: Streamlit Secrets 또는 환경변수
- `.env`는 `.gitignore`에 등록, API Key 하드코딩 금지
- 오류 문구에 키나 요청 주소를 넣지 않는다
- `st.cache_data(ttl=600)`로 성공한 응답만 10분 캐시, 타임아웃 5초
- 401(키 오류·미활성), 429(요청 많음), 그 밖의 오류를 각각 안내한다

## 5. UX Writing

### 작성 원칙

- 친구처럼 친근하고 재치 있는 말투
- 짧고 명확한 한 줄 메시지
- 과도한 유행어 및 이모지 사용 지양
- 실제 날씨와 모순되는 표현 금지
- 위트 있는 문장 아래 구체적인 추천 아이템 표시
- 문구는 조건별 템플릿으로 관리 (`data/rules.json`)

### 문구 예시

| 조건 | UX Writing |
|---|---|
| 28°C 이상 | 오늘은 반팔도 더울 각! (내일 탭에서는 "내일은 …") |
| 23~27°C | 가볍게 입고 나가도 좋겠어. |
| 17~22°C | 반팔만 입기엔 살짝 애매해. |
| 12~16°C | 재킷 하나 걸치면 딱! |
| 6~11°C | 코트 출동할 타이밍. |
| 5°C 이하 | 패딩 안 입으면 후회할지도? |
| 강수확률 높음 | 우산 없이 나갔다간 머리 감기 2회차. |
| 너무 추움 | 손끝까지 얼 기세. 핫팩 하나 챙겨! |
| 너무 더움 | 땀 주의보! 물은 꼭 챙겨. |
| 기온 차 큼 | 낮에 속지 마. 저녁엔 추워! |
| 햇빛 쨍쨍 | 햇빛 쨍쨍! 선글라스 끼고 나가자. |

- 추천 문구는 날씨 조건, 시간대(오전·오후·저녁), 날짜(오늘·내일)에 따라 바뀐다
- 질문 문구: "오늘 뭐 입지?", "내일 아침엔 뭐 입지?", 여러 칸이면 "9시~18시 외출엔 뭐 입지?"
- 말풍선 문장: 준비물마다 3개씩, 매번 무작위로 고른다 (예: "추우니까 목도리 가져갈까?")

## 6. UX/UI 구성

### 화면 순서

0. (접속할 때마다) 소개 + 내 정보(닉네임·성별·지역·미니미 얼굴)
1. 헤더: MOIPJI 로고, 슬로건, 화면 모드(브라이트/어두움), 톱니바퀴(내 정보 설정), (좁은 화면) '=' 메뉴. 화면에 고정하지 않고 함께 스크롤된다
   - 그 아래 지역 선택 (스크롤된다)
2. 날짜(오늘/내일), 외출할 시간(48시간 가로 스크롤 + 전용 스크롤바), 외출 시간 확정, 날씨 새로고침
3. 추천 카드: 질문, 한 줄 결론, 핵심 안내, 날씨·체감 구간, 코디 설명
4. 히어로: 왼쪽 외출 날씨 요약 / 오른쪽 말풍선·미니미·풍경, `<` ○○ 챙기기 `>`, 옷장에 저장
5. 옷 고르기: 스타일 선택, 입은 상의·하의·아우터 카드(색상 선택 팔레트), 다른 아이템 둘러보기 토글 → 스타일 아이템 고르기(탭 + 선택 버튼), 추천 코디로 되돌리기
6. 챙길 것 카드(챙기기 토글, 색상 선택 팔레트), 날씨 및 추천 근거
7. 내 옷장 (리스트/썸네일)
8. 출처: "날씨 정보는 OpenWeather에서 가져와요." + 불러온 시각

### 디자인

- **Atmospheric Glass**: 날씨 상태에 따라 배경 그라데이션이 바뀐다 (맑은 낮·맑은 밤·흐림/비), 카드는 반투명 유리 + 얇은 테두리, 그림자 없음
- **브라이트 / 어두움 모드**: 맨 위 오른쪽 토글. 브라이트는 밝은 그라데이션에 어두운 글자, 어두움은 어두운 그라데이션에 흰 글자 (날씨별 색조는 유지). 처음엔 저녁 6시~아침 6시면 어두움, 아니면 브라이트. 두 모드 모두 글자 대비 4.5:1 이상
- **싸이월드 도트 그래픽**: 도트 글꼴(갈무리)과 계단형 모서리, 도트 아이콘·캐릭터
- **싸이월드 다이어리 외곽 프레임** (`theme.py`, 서비스 화면은 그대로 두고 바깥 레이어만 입힘)
  - 바탕: 대표색이 옅게 섞인 도트 무늬 / 바깥 프레임: 대표색 파스텔(MOIPJI는 블루 `#7FA6D3`), 둥근 모서리, 얇은 테두리, 옅은 그림자 / 안쪽 페이지: 크림 테두리 + 날씨 그라데이션
  - **대표색**: `theme.SERVICE = Service("weather", "MOIPJI", "#7FA6D3")` 한 줄. 프레임·테두리·탭 색은 대표색 하나에서 자동으로 만들고, 탭 글자는 대비 4.5:1 이상이 되게 어둡게 한다
  - **팀원 수정 규칙은 합의 전이라 `theme.py` 끝에 주석으로만 둔다**: 서비스마다 route·서비스명·대표색을 한 줄씩 두는 `SERVICES`, `render_frame(route)`·`render_gnb(route)`, `shared/theme.py`로 옮기기. 지금 코드로 켜 두면 다른 서비스가 import할 때 팀 규칙에 어긋나고 MOIPJI 전용 값이라 오류가 날 수 있어서다
  - 오른쪽 탭은 팀 서비스로 이동하는 **GNB**: JOOYOU · guest · meal · reading · MOIPJI. 병합 앱의 각 서비스 페이지(`fuel`, `guest`, `meal`, `reading`, `weather`)로 이동한다. 지금 서비스(MOIPJI) 탭은 대표색 테두리·왼쪽 띠·글자로 강조한다. 다른 서비스 색은 합의 전이라 정하지 않는다
  - 넓은 화면: 세로 탭은 프레임 오른쪽 테두리 끝에 붙어 있다 (처음 디자인처럼 화면에 고정되어 스크롤해도 그 자리에 있다. 머리글은 고정하지 않는다)
  - 좁은 화면(1060px 이하): 프레임 여백·그림자를 줄이고, 세로 탭 대신 톱니바퀴 오른쪽 '=' 메뉴 버튼으로 같은 GNB를 연다 (오른쪽에 맞춰 펼침, 바깥을 누르거나 Esc로 닫힘)
- 글꼴: 로고·기온·제목·버튼은 갈무리(Galmuri11/14), 긴 글은 Pretendard
- 로딩 중에는 스켈레톤 대신 배경이 은은하게 물결친다. 오류 화면은 빗방울 맺힌 유리 위에 안내를 띄운다
- 지역 선택 상자는 흰 바탕에 검은 글자
- 접근성: 본문 대비 4.5:1 이상을 목표로 하고, 색만으로 구분하지 않도록 이름·아이콘을 함께 쓴다. 움직임 줄이기 설정을 존중한다

### UI 원칙

- 모바일 퍼스트 반응형 (390px에서 가로 넘침 없음)
- 터치하기 쉬운 컨트롤 (버튼 높이 44px 이상)
- 장식은 화면을 해치지 않는 선에서, 애니메이션은 짧게
- Streamlit 기본 컴포넌트를 우선 활용하고, 모양은 페이지 범위 CSS로 입힌다

## 8. 개발 규칙

1. Python 3.14 환경을 사용한다.
2. OpenWeatherMap API만 연동한다.
3. AI API 및 데이터베이스는 사용하지 않는다. 옷장은 로컬 JSON 파일에 저장한다.
4. 날씨 조회, 데이터 가공, 코디 추천, 문구 선택, 그림 그리기를 함수로 분리한다.
5. 코디 추천은 Python 조건문 및 JSON 데이터로 구현한다.
6. 날짜·외출 시간·스타일·색·준비물을 바꾸면 결과가 함께 갱신되어야 한다.
7. 이미지가 없어도 서비스가 정상 동작해야 한다.
8. 실제 API 데이터가 없으면 임의의 날씨를 생성하지 않는다.
9. API Key를 GitHub에 노출하지 않는다.
10. 팀의 다른 서비스 파일 및 공통 구조는 임의로 수정하지 않는다.

## 11. 알려진 한계

- 시간별 날씨는 3시간 간격이다. 1시간 간격은 OpenWeather 유료 구독(One Call 3.0)이 필요하다
- 자외선 정보가 없어 햇빛 판단은 하늘 상태로 대신한다
- 옷장은 앱이 실행되는 컴퓨터의 파일에 저장된다. 배포하면 모든 방문자가 같은 옷장을 쓰고, 재배포 시 지워질 수 있다
- 내 정보는 접속마다 따로라 방문자끼리 섞이지 않지만, 새로고침·링크 이동·앱 재시작 때마다 다시 입력해야 한다
- 맑은 낮 배경(민트) 위 흰 글자는 대비가 낮아 글자 그림자로 보완하고 있다
- 미니미 풍경은 Streamlit이 SVG를 이미지(`<img>`)로 넣는다. 브라우저 움직임 줄이기를 흉내 낸 테스트에서는 이미지 안의 애니메이션이 멈추지 않았다 (SVG를 페이지에 직접 넣으면 멈춤). 실제 OS 설정에서는 확인하지 못했다
- 포즈 동작은 그림이 바뀔 때마다 다시 재생된다 (우산 색만 바꿔도 다시 펼친다)
- 실행 중인 앱에서 `minimi.py`·`theme.py`를 고치면 Streamlit이 예전 모듈을 그대로 쓸 때가 있어(예: `ImportError: cannot import name 'render_greeter'`), `weather.py`가 매 실행 때 두 파일의 수정 시각을 보고 바뀌었으면 다시 읽는다
- GNB 링크는 병합 앱의 페이지 주소를 가리킨다. MOIPJI만 단독 실행하면 다른 서비스 페이지가 없어 Streamlit이 "페이지 없음" 후 첫 페이지로 돌려보낸다. 링크로 이동하면 새로 접속한 것과 같아서 화면 상태(고른 외출 시간 등)는 초기화된다 (옷장은 파일이라 유지되고, 내 정보는 다시 입력한다)
- 대기질 예보는 오늘 지난 시간 값을 주지 않는다. '지금' 칸은 현재 시각 이후 값으로 판단한다
